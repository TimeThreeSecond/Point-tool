## 五、构建系统说明

### 5.1 两种构建方式的对比

| 构建方式 | 生成器 | 状态 | 说明 |
|---------|--------|------|------|
| **手动构建（推荐）** | Ninja | 可用 | 通过 `build_and_run.bat` 运行 |
| **Flutter 工具构建** | Visual Studio 17 2022 | 失败 | MSBuild 子进程找不到 `libucrt.lib` |

### 5.2 为什么 Flutter 工具构建失败？

**根本原因**: VS Build Tools 安装在非标准路径 `D:\Android\VSBuildTools`，而 `flutter run -d windows` / `flutter build windows` 使用 **Visual Studio 生成器** 调用 MSBuild。MSBuild 启动的编译/链接子进程**无法继承**用户环境变量中的 `LIB`/`INCLUDE` 路径。

**具体错误**:
```
LINK : fatal error LNK1104: 无法打开文件"libucrt.lib"
```

**原因分析**:
1. MSBuild 在构建 `.vcxproj` 时会重新解析环境变量
2. 在非标准安装路径下，`VCTargetsPath` 解析错误：`v170Platforms\x64\Platform.props`（错误）vs `v170\Platforms\x64\Platform.props`（正确）
3. 导致 `LIB` 和 `INCLUDE` 没有被正确传递给 `link.exe`

### 5.3 为什么 Ninja 构建成功？

**原因**:
1. Ninja 直接使用 `cmd /c` 调用 `cl.exe` 和 `link.exe`
2. 通过 `vcvarsall.bat` 设置了当前 shell 的环境变量
3. 子进程正确继承了 `LIB` 和 `INCLUDE`，能够找到所有库文件
